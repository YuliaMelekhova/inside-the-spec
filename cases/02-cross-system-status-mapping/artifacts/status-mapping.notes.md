## Purpose
Use status-mapping.csv as the sole maintained source for the source-status dictionary, mapping version, and terminal markers. The dictionary embedded in specification.md is generated by verify.py; edit the CSV and rerun that script.

The key is (contract_version, source_system, object_type, raw_status, inspection_result). Values are case-sensitive, with no trimming or uppercase conversion. An empty CSV result means the JSON field must be absent, not null or an empty string. WMS IN_PROGRESS with any inspection_result is invalid; WMS COMPLETED requires ACCEPTED or REJECTED. Other object types forbid inspection_result.

UNKNOWN is the default for absent valid evidence, not a source state or a terminal state. Terminal refers to ordinary event processing; an audited authoritative re-baseline can correct a terminal fact. All rows use contract_version=1 and mapping_version=0.3. These are distinct version domains.

Apply identity checks before content checks. Use the decision table after mapping; this CSV does not directly map raw statuses to UI text.


## Issuance is not finality
PSP COMPLETED is nonterminal in mapping version 0.3. A newer valid FAILED snapshot is a permitted transition and invokes financial-exception handling. FAILED is terminal for this one-refund object; a new refund attempt is a different object and outside this case. The same four PSP projection values still produce 64 state tuples. Neither FAILED nor COMPLETED proves that a ledger balance has changed in a particular way.
